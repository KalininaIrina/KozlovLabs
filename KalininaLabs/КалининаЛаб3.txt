ЛАБОРАТОРНАЯ РАБОТА № 3
Основы контейнеризации: запуск, сборка образов и многоконтейнерные приложения в Docker

Выполнила: Калинина Ирина, группа ГИ-41

Цель работы: изучить базовые принципы работы с Docker, освоить запуск и управление контейнерами, создание пользовательских образов с помощью Dockerfile и развертывание связанных сервисов через Docker Compose.

Задание: запустить готовый Nginx, отдать свою HTML-страницу через том, собрать собственный образ transport-app, поднять связку веб-сервер + Redis через Docker Compose и зафиксировать файлы в репозитории.

Работа выполнена локально в Docker Desktop (Docker 27.5.1, Compose v2.32.4). Google Cloud Shell и GitHub Codespaces не использовались: для них нужен отдельный вход в браузере. Команды и проверка страницы те же, что в методичке.

1. Запуск базового контейнера

Проверена версия:
docker --version
Docker version 27.5.1, build 9f9e405

Запущен готовый веб-сервер, порт 8080 хоста проброшен на порт 80 контейнера:
docker run -d -p 8080:80 nginx

Контейнер поднялся, идентификатор 1bb00de755d5. Фрагмент вывода docker ps:
CONTAINER ID   IMAGE   PORTS                    NAMES
1bb00de755d5   nginx   0.0.0.0:8080->80/tcp     epic_dijkstra

Проверка страницы:
curl http://127.0.0.1:8080/
HTTP 200, в ответе заголовок Welcome to nginx!

Контейнер остановлен:
docker stop 1bb00de755d5

2. Своя страница через том (задание 1)

Создан файл index.html со страницей информационной системы. В начале файла указана кодировка utf-8, иначе браузер Windows открывал русский текст некорректно.

Контейнер запущен с монтированием текущей папки:
docker run -d -p 8080:80 -v ${PWD}:/usr/share/nginx/html --name my-nginx nginx

По адресу http://127.0.0.1:8080/ отобразился текст:
«Система оформления электронных перевозочных документов»
«Модуль регистрации заявок активен.»

Контейнер остановлен и удален:
docker stop my-nginx
docker rm my-nginx

3. Собственный образ (задание 2)

Файл Dockerfile:

FROM nginx:alpine
COPY index.html /usr/share/nginx/html/index.html
EXPOSE 80

Сборка и запуск:
docker build -t transport-app .
docker run -d -p 8080:80 --name my-custom-app transport-app

docker ps показал контейнер my-custom-app из образа transport-app, порт 0.0.0.0:8080->80/tcp. Страница по порту 8080 совпала со своей HTML-страницей. После проверки контейнер остановлен и удален:
docker stop my-custom-app
docker rm my-custom-app

4. Docker Compose (задание 3)

Файл docker-compose.yml описывает два сервиса. web берет уже собранный образ transport-app и публикует порт 8080. cache использует redis:alpine и публикует порт 6379. Директива depends_on заставляет web стартовать после cache.

docker compose up -d

Вывод docker compose ps:
NAME               IMAGE           SERVICE   PORTS
3_docker-cache-1   redis:alpine    cache     0.0.0.0:6379->6379/tcp
3_docker-web-1     transport-app   web       0.0.0.0:8080->80/tcp

Имя проекта 3_docker получилось из имени папки лабораторной. Страница на порту 8080 снова отдала текст системы. Проверка Redis:
docker exec <контейнер cache> redis-cli ping
PONG

Compose выдал предупреждение, что поле version в файле устарело. Строка version: '3.8' оставлена, потому что так задано в методичке.

6. Ответы на контрольные вопросы

1. В чем принципиальное отличие Docker-контейнера от классической виртуальной машины?
Контейнер работает на ядре операционной системы хоста и не содержит отдельной гостевой ОС. Виртуальная машина запускает свою ОС через гипервизор, поэтому она тяжелее и дольше стартует.

2. Для чего в команде docker run применяются ключи -d и -p?
-d запускает контейнер в фоновом режиме. -p публикует порт контейнера на порт хоста. В работе использовалось -p 8080:80: снаружи порт 8080, внутри контейнера порт 80.

3. Какая директива в Dockerfile отвечает за перенос файлов с компьютера разработчика внутрь создаваемого образа?
COPY. В образе transport-app этой директивой копируется index.html.

4. Почему в задании 1 использовалось монтирование тома (флаг -v), а в задании 2 — команда COPY?
Флаг -v подключает папку с хоста в контейнер. Файл можно менять, и Nginx сразу отдает новую версию, образ пересобирать не нужно. COPY записывает файл в образ во время docker build. После сборки контейнер не зависит от файла на хосте: страница уже лежит внутри образа.

5. Какую функцию выполняет директива depends_on в файле docker-compose.yml?
Она задает порядок запуска. Сервис web стартует после сервиса cache. Это не проверка того, что Redis уже принимает команды, а только порядок старта контейнеров.

6. Что произойдет при выполнении команды docker compose down в директории с проектом?
Команда остановит и удалит контейнеры стека и сеть, которую создал compose up. Образы transport-app и redis:alpine останутся на машине. Отдельных именованных томов в этом файле нет.
